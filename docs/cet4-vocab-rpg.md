## 0. 阅读指南

### 0.1 文档目的

本文档是《四级单词跑团》的唯一实现依据。默认数值、状态机、数据结构和验收标准都可以直接落库、落代码。文中使用以下约定：

- **必须**：MVP 验收项，缺失即不通过。
- **应当**：默认实现，除非有明确理由。
- **可以**：可选增强，不阻塞 MVP。
- 所有时间均为用户本地时间；"学习日"以本地时间 04:00 为分界（见 3.8）。

### 0.2 术语

| 术语 | 含义 |
| --- | --- |
| 词卡 | 一个 CET-4 单词及其释义、例句、行动类型、效果和失败代价 |
| 契约 | 新词首次出现时的"认识 + 当次小测"，通过后进入 SRS |
| 复习 | 对到期词卡的主动回忆测试，结果决定下次间隔 |
| 场景 | 剧情的最小单位，包含旁白、若干新词契约和 1–2 次词行动 |
| 词行动 | 在剧情中选一张词卡、回忆英文并结算效果 |
| 检定 | 词行动的同义词；答对即检定成功，答错即失败 |
| HP | 每章独立的体力值，失败扣血，归零触发"力竭"而非删档 |
| 线索 | 每章最多可获得 3 条，失败会丢失，可用于解锁支线/结局文本 |
| 分支 | 失败后进入的"代价剧情"，仍然继续，不卡关 |
| 已认识 | 用户主动跳过、并通过验证的词，不进入 SRS |
| 补测 | 契约答错后，该词在随后的剧情行动中再被测试一次；不改变"1 天"排期 |

### 0.3 六条核心约束

| 需求 | 落地位置 | 验收口径 |
| --- | --- | --- |
| 默认标准档 15 分钟（5 分钟 SRS + 10 分钟剧情），可切 5/10/15/18/20 分钟档位 | 2.1–2.6 | 标准档 12 新词/天实测 13–17 分钟；5–8 分钟原型档可用 |
| 答对间隔 ×2（1/3/7/16 天），答错回 1 天；正式档每天新词 10–20，复习优先 | 3.2–3.5 | 调度单测全部通过；新词在复习清空前不可用；原型档 0–4 不算正式进度 |
| 单词即行动，失败有剧情代价（HP/线索/分支） | 4.1–4.4 | 每次词行动都必须回忆英文；失败必结算一种代价 |
| 6 章，每章 30–50 词，按 CET-4 词频排序 | 5.1–5.4 | 6 章 × 48 词 = 288 词；词频严格递增 |
| 固定习惯锚点、进度可见、异步/社交、已认识跳过 | 6.1–6.5 | 设置锚点、首页进度、分享/挑战、跳过验证均可用 |
| 避开：一次背太多、只读不测、没有复习、剧情过重 | 第 7 章 | 上线前检查清单逐条勾选 |

### 0.4 关键数值速览

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 章节/词量 | 6 章 × 48 词 = 288 词 | 每章 30–50 词范围内 |
| 每日新词（正式档） | 12 个（可设 10/12/15/20） | 硬上限 20；原型档 0–4 为独立演示会话 |
| 每日循环 | 默认标准档 5 分钟复习 + 10 分钟剧情 | 支持 5/10/15/18/20 分钟档位；短原型档 5–8 分钟 |
| 复习间隔 | 1 / 3 / 7 / 16 天 | 16 天封顶；答错回 1 天 |
| 每章 HP | 100 | 失败 -10/-15/-20；力竭回 50 |
| 每章线索 | 最多 3 条 | 失败 -1，可复习找回 |
| 每章场景 | 12 个 × 4 新词 | BOSS 为第 12 场景 |
| BOSS | 5 个词检定 | 成功 ≥3 净化；失败可继续 |

### 0.5 范围

- **MVP 覆盖**：由素材管线生成的 CET-4 词频最高的 288 个词，6 章，单机 + 异步社交。
- **MVP 不覆盖**：4500 词全量课程、实时多人、真人语音评分、复杂战斗动画。
- **扩展方式**：以"第二季词包"继续按词频向后取词，不改核心循环。

## 1. 产品定位

### 1.1 一句话

你是一名"拾词者"，在语言正在消失的"词境"里前行。每一道门、每一场雾、每一个敌人，都只能用单词解决；而你每天只需要 15 分钟——忙时 5 分钟也能推进一小段。

### 1.2 目标用户

- 18–24 岁、正在备考 CET-4 的大学生。
- 每天有 3–5 段碎片时间，但很难坚持打开单词 App。
- 能接受文字跑团/视觉小说，不喜欢重度战斗和长时间养成。
- 核心诉求不是"背完 4500 词"，而是"高频词真正记住、每天能坚持"。

### 1.3 要解决的问题

1. **背了就忘**：没有按遗忘曲线复习，或复习不优先。
2. **只读不测**：看释义觉得会，合上书想不起来。
3. **难坚持**：一次背太多、断签即放弃、进度不可见。
4. **游戏与学习两张皮**：剧情很长，单词只是背景板。

### 1.4 设计原则

1. **复习优先**：到期复习没清完，今天不学新词。
2. **检索优先**：每一次接触词，最终都要以"答出来"结束，不存在"翻卡即学会"。
3. **词为剧情服务**：先有当天要学的词，再写场景；不为了剧情硬塞生词。
4. **失败有代价，但绝不卡关**：扣 HP、丢线索、走代价分支，但剧情永远有下一幕。
5. **档位封顶**：标准档 15 分钟（13–17 分钟浮动）、深度档 20 分钟；任何系统不能把用户拖进无限刷词。
6. **单机可玩，社交异步**：不要求好友同时在线也能获得社交支持。

### 1.5 非目标

- 不做 4500 词全覆盖的"词典课程"；MVP 只做高频核心 288 词。
- 不做实时组队、实时 PVP、语音房。
- 不做复杂装备/数值养成；卡牌只有"词卡"一种。
- 不做重美术；以文字、图标、少量氛围插画为主。
- 不把"已认识"当作学习成果；跳过词不计掌握、不给经验。

## 2. 核心循环：15 分钟标准档，可切短档/长档

### 2.1 每日时间轴（标准档：15 分钟 / 12 个新词）

| 时间 | 阶段 | 玩家在做什么 | 系统在做什么 |
| --- | --- | --- | --- |
| 0:00–0:30 | 今日任务 | 看今日任务卡：到期复习 X 张、新词 12 个、剧情目标 | 计算每日计划，显示预计时长 |
| 0:30–5:30 | 记忆神殿（SRS） | 快问快答到期词；答错看正确答案 | 记录结果，更新 1/3/7/16 间隔 |
| 5:30–6:00 | 转场 | 确认复习已清空，进入剧情 | 解锁新词配额，载入章节场景 |
| 6:00–14:30 | 剧情推进 | 3 个场景；每场 4 个新词契约 + 1–2 次词行动 | 结算成功效果 / 失败代价，推进分支 |
| 14:30–15:00 | 结算 | 看战报、明日预告、打卡 | 更新 streak、章节进度、明日队列 |

> 15 分钟是**默认标准档**，不是唯一档位：5 分钟复习 + 约 10 分钟剧情；任务卡、转场与结算各 15–30 秒，实际剧情时长通常为 8–10 分钟。短原型档、轻量档、加速档、深度档见 2.6；设置页必须如实显示每个档位的预计时长。

### 2.2 一次完整会话的步骤

1. **进入**：打开 App，若当天未开始则创建 `session`；若已开始未完成则续接。
2. **算计划**：按 2.5 生成 `due` 队列与 `new` 队列；显示"复习优先"提示。
3. **复习**：逐张回答到期词。答对进入下一张；答错当场显示正确答案与例句，记为失败并排到明天（1 天），不阻塞当前会话。
4. **复习闸门**：只有 `due` 全部答完，才解锁新词。若复习未清空就中途退出，今日不发放新词，已答结果立即保存。
5. **剧情**：按顺序播放场景。每个场景先发 4 个新词契约（原型档 2–4 个演示词），再进入旁白与词行动。
6. **词行动**：玩家选择行动 → 输入/说出英文 → 服务端判定 → 成功结算效果；失败结算 HP/线索/分支，并让该词回到 1 天间隔。
7. **收尾**：当日场景结束（标准档 3 个）或本档剧情预算用完，进入结算；保存进度，展示明日到期数。

### 2.3 会话状态机

```text
idle
  └─ start ──> review ──(due 清空)──> story ──(场景/时间结束)──> summary ──> done
                 │                        │
                 │                        └─(剧情未完成)──> paused
                 ├─(中途退出)──> paused
                 └─(到期 > 85 且选择只复习)──> summary
```

- `paused` 可在当天恢复；跨天后 `due` 按自然到期重新计算，剧情进度保留。
- 状态转换必须服务端校验；客户端只能请求，不能直接改 `due_on`、`hp`、`clues`。
- 每日 `session` 幂等：同一天重复进入返回同一个未完成会话，不重复发放新词。

### 2.4 时间预算与超时保护

| 阶段 | 预算 | 超时行为 |
| --- | --- | --- |
| 复习 | 标准档 5 分钟（原型 2 / 轻量 3） | 到预算时弹窗："还剩 N 张，冲刺 2 分钟 / 今天只复习"；不硬切当前卡 |
| 剧情 | 标准档 10 分钟（原型 3–6 / 轻量 7–10 / 深度 15） | 到预算时在最近一个词行动结算后暂停，展示"今日可到此为止"；不截断未结算的行动 |
| 整局 | 标准档 15 分钟 | 超过档位预算 5 分钟必须提示"今天已经很棒了"，并给出结束按钮 |

**超时不是失败**：未完成内容顺延，不计断签，不扣 HP。避免"玩到一半被系统踢出"的挫败感。

### 2.5 每日计划生成

```ts
type Plan = {
  tier: 'prototype' | 'light' | 'standard' | 'accelerated' | 'deep';
  due: WordCard[];        // 到期复习，按 due_on 升序
  newWords: WordCard[];   // 今日新词，按词频升序
  mode: 'normal' | 'fast' | 'sprint' | 'review_only';
  newBudget: number;      // 0 或 10..20；原型档 0–4 在会话层覆盖
};

function buildPlan(user, today, tier): Plan {
  const due = getDueCards(user, today)          // state ∈ {review, mastered} 且 due_on <= today
    .sort(byDueAscThenLapsesDescThenFreqAsc);

  const backlog = due.length;
  let mode: Plan['mode'] = 'normal';
  if (backlog > 85) mode = 'review_only';
  else if (backlog > 65) mode = 'sprint';
  else if (backlog > 45) mode = 'fast';

  // 复习优先：普通日按用户设置，且必须落在 10..20；review_only 日默认 0
  // 原型档不进入正式 newWords 队列；它的 2–4 个演示词由 session 层单独发放
  let newBudget = tier === 'prototype' ? 0 : (mode === 'review_only' ? 0 : clamp(user.newPerDay, 10, 20));

  // 用户可在 review_only 日显式选择"仍学 10 词"：
  // 此时 mode 改为 'sprint'，newBudget = 10，并显著提示 backlog。

  const newWords = getNextNewWords(user.currentChapter, newBudget); // 未契约、非 known，按 freq_rank 升序
  return { due, newWords, mode, newBudget };
}
```

规则：

- **复习优先**是硬规则：`due.length > 0` 时，新词卡在 UI 上保持锁定，只有复习清空后才解锁。
- 每日新词数硬边界 `[10, 20]`；只有"复习优先日"、"用户主动选择只复习"和"原型档"允许 0–4（原型档不写正式进度）。
- 新词顺序 = 当前章内 `freq_rank` 升序；不允许跳词（`known` 跳过除外）。
- 若当前章新词已发完，且章节 BOSS 已尝试，则解锁下一章；否则今日只复习 + 补剧情。

### 2.6 会话档位与时长

15 分钟是**默认标准档**，不是硬性要求。产品提供以下档位；原型档专用于验证核心循环，不写正式进度。

| 档位 | 总时长 | 复习 | 剧情 | 新词/天 | 场景/天 | 用途 |
| --- | --- | --- | --- | --- | --- | --- |
| 原型档 | 5–8 分钟 | 2 分钟（≤10 张） | 3–6 分钟（1–2 场景） | 0–4（会话级覆盖，不写用户设置） | 0.5–1 | 验证循环/演示 |
| 轻量档 | 10–13 分钟 | 3 分钟（≤20 张） | 7–10 分钟（2–3 场景） | 10 | 2.5–3 | 忙碌日/复习多 |
| 标准档（默认） | 15 分钟 | 5 分钟（≤45 张） | 10 分钟（3 场景） | 12（可设 10–20） | 3 | 正式学习 |
| 加速档 | 17–18 分钟 | 5 分钟 | 12–13 分钟（约 3.75 场景） | 15 | 3.75 | 有时间的加速 |
| 深度档 | 20 分钟 | 5 分钟 | 15 分钟（5 场景） | 20 | 5 | 冲刺/周末 |

规则：

- **正式学习档**（轻量/标准/加速/深度）的新词数仍受 10–20 硬边界约束；原型档的 0–4 是唯一例外。
- **原型档使用独立会话**：不发正式新词、不写 `user_progress`、不计 streak/周报，可随时重置；复习结果默认不写 SRS，避免演示污染正式数据（可在设置里显式打开）。
- 原型档每场景可用 2–4 个演示词，只需验证"词即行动 + 失败代价 + 短会话循环"是否成立，不追求内容完整；可只做 1 个场景。
- 正式档场景固定按 4 个新词制作，`场景数 = newBudget / 4`，允许在场景中途按"词行动结算点"暂停。
- 设置页显示每个档位的预计时长；不允许"无限时长"。
- 切换档位不改变 SRS 规则（1/3/7/16）与复习优先；`due > 65` 时建议 10 词，`due > 85` 时默认只复习。
- 不允许出现"无限新词""一次导入 100 词"入口。

### 2.7 首日、回归与轻量日

- **首日**：不发新词，只做 5 分钟"词境入门"——10 张极高频词样例（教学用）+ 1 个教学场景，让用户理解"词即行动"；次日进入正式循环。
- **回归（≥3 天未学）**：先做"回归复习"（最多 20 张到期词），再发 10 个新词；不扣 streak 的历史，不要求补完所有欠账。
- **轻量日**：用户可点"今天只复习"或"只做 2 分钟"；"只复习"清完到期即算保底打卡，"2 分钟"只做 10 张复习。
- **断签**：未完成保底才断签；断签不清进度、不清词库、不清章节。

## 3. 间隔重复（SRS）

### 3.1 词卡状态

| 状态 | 含义 | 是否进入复习队列 |
| --- | --- | --- |
| `new` | 尚未契约 | 否 |
| `review` | 已契约，stage 0–2 | 是 |
| `mastered` | stage 3，16 天间隔 | 是 |
| `known` | 用户验证"已认识" | 否（仅 BOSS 抽查） |

一个词在同一用户下只有一条 `user_word` 记录；状态迁移必须服务端原子完成。

### 3.2 1/3/7/16 天阶梯

**规则：答对升一档，间隔变为下一档；答错立即回到 1 天；16 天封顶。**

| 阶段 `stage` | 场景 | 下次复习间隔 | 进入条件 |
| --- | --- | --- | --- |
| `-1` | 未契约 | — | 新词 |
| `0` | 契约完成 | **1 天** | 契约小测结束（无论对错，先按 1 天安排） |
| `1` | 第 1 次复习答对 | **3 天** | `stage 0` 答对 |
| `2` | 第 2 次复习答对 | **7 天** | `stage 1` 答对 |
| `3` | 第 3 次复习答对（mastered） | **16 天** | `stage 2` 答对 |
| `3` | 之后每次答对 | **16 天**（封顶） | `stage 3` 答对 |
| `0` | 任意一次答错 | **1 天** | 任意 stage 答错 |

> `stage = -1` 只存在于新词队列的内存模型，不写入 `user_words`；契约完成后才创建记录（`stage 0`）。

实现要点：

- 采用**固定表** `INTERVALS = [1, 3, 7, 16]`，不要用浮点 `×2` 计算，避免 1→2 与题设 1→3 不一致。
- "答对间隔 ×2"在题设中给定了 1/3/7/16 的近似倍增阶梯，实现以本表为准。
- 16 天为 MVP 上限；未来"长间隔模式"可扩到 32/64 天，但不属于本期。

### 3.3 调度算法

```ts
const INTERVALS = [1, 3, 7, 16]; // days

function introduce(word: UserWord, correct: boolean, today: LocalDate) {
  word.state = 'review';
  word.stage = 0;
  word.dueOn = addDays(today, INTERVALS[0]); // 契约后 1 天
  word.lastResult = correct;
  word.introducedAt = today;
}

function review(word: UserWord, correct: boolean, today: LocalDate) {
  if (correct) {
    word.stage = Math.min(word.stage + 1, 3);
    word.correctStreak += 1;
  } else {
    word.stage = 0;
    word.correctStreak = 0;
    word.lapses += 1;
  }
  word.dueOn = addDays(today, INTERVALS[word.stage]);
  word.state = word.stage === 3 ? 'mastered' : 'review';
  word.lastResult = correct;
  word.lastReviewedAt = now();
}
```

- 契约阶段不论对错都进入 `stage 0 / 1 天`；对错只影响"契约是否通过"的提示，不影响该词能否在本场景行动中使用。
- 契约答错的词若出现在本场景行动中，会被"补测"一次；补测失败照常结算剧情代价，但仍只排 1 天；未出现在行动中的，次日正常复习。
- 剧情中词行动失败，同样调用 `review(word, false, today)`：**剧情失败 = 一次答错**，间隔回到 1 天。剧情成功不改变 SRS 排期（避免用户靠重复刷剧情"刷间隔"）。
- 一次回答只允许调用一次调度；重复提交用幂等键去重（见 8.5）。
- 时区/跨天以"学习日"为准：本地 04:00 之前仍算前一天（见 3.8）。

### 3.4 每日复习队列

排序键（从主到次）：

1. `due_on` 升序（拖得最久的先复习）。
2. `lapses` 降序（错得多的先复习）。
3. `freq_rank` 升序（高频词优先）。
4. `word_id` 字典序（稳定排序）。

队列规则：

- 每日开始只取 `due_on <= 今日学习日` 的卡；未来卡不提前出现。
- 复习模式按 backlog 自动切换：

| 到期数 | 模式 | 单卡预算 | 展示方式 |
| --- | --- | --- | --- |
| ≤ 45 | normal | 约 6 秒 | 英文 → 4 选 1 中文 |
| 46–65 | fast | 约 4.5 秒 | 英文 → 3 选 1 中文 |
| 66–85 | sprint | 约 3.5 秒 | 英文 → 2 选 1 中文（或"认识/不认识"自评） |
| > 85 | review_only | — | 建议只复习；新词默认 0，用户可显式改为 10 |

- 复习界面不展示例句、不展示词根提示，只有"提交/跳过"；跳过视为答错；答错后才展示正确答案 + 例句 + 记忆提示。
- 每张卡回答后立即显示 600ms 的对错反馈，不等待整轮结束。

### 3.5 新词、复习优先与配额

- **新词只能从当前章按 `freq_rank` 顺序取**，不允许跨章跳词。
- **复习清空前，新词锁定**。UI 显示："先清完到期复习，词灵才会回应你。"
- 每日新词硬上限 20、硬下限 10（复习优先日/用户主动只复习除外）。
- 新词不足 10 个时（章末、词表耗尽）按实际剩余发放；次日新章恢复 10–20。
- 新词配额与复习量的推荐关系：`due > 65` 时建议 10；`due > 85` 时默认只复习。系统只建议，不偷偷改用户设置；用户确认后才生效。

### 3.6 答错处理与顽固词

- 答错：显示正确答案、音标、例句；记录 `lapses + 1`；`stage = 0`、`due = 明天`。
- **当场不强制重测**，避免复习超时；用户可点"再试一次"，最多重测 5 张，重测结果仍按答错处理（不再改间隔，只用于巩固）。
- **顽固词**：`lapses >= 4` 的词标记为 `leech`，在复习结束后追加一个可选的"顽固词小练"（最多 5 张，拆词根/联想/例句），不改变当天到期规则；连续 3 次答对后移除 `leech` 标记。
- **连续答对**：`correctStreak` 只用于展示和顽固词判断，不影响 16 天封顶。
- **答题超时**：超过 20 秒未作答视为答错，但显示"慢慢来"提示；语音/输入法场景可放宽到 30 秒。

### 3.7 "已认识"跳过

入口：仅在新词契约卡上提供，文案"这个词我已经认识"。

验证（随机抽 1 项，必须通过）：

1. 看中文，输入英文（精确匹配，忽略大小写和首尾空格）。
2. 听发音（TTS），从 4 个拼写中选正确项。
3. 看英文，从 4 个中文释义中选正确项。

结果：

- **通过**：`state = known`，移出 SRS 与新词队列；章节进度记为"已认识"，**不给经验**；可在词书中撤销。
- **不通过**：进入正常契约，`stage 0 / 1 天`，文案"先交给记忆神殿吧"。
- **数据**：`known` 词仍写入 `user_words`（`state = known`、`stage = 0`、`due_on = 明天`），只是不进入复习队列；撤销时直接改回 `review`。
- **防滥用**：每章 BOSS 有 10% 概率（最多 1 个）抽一个 `known` 词做"封印确认"；失败则 `known = false`，重新进入 SRS（`stage 0 / 1 天`），但不扣 HP。跳过的词不计入"已掌握"，不计入"掌握率"。
- 不允许批量跳过、不允许跳过整个章节。

### 3.8 跨天、时区与补复习

- 学习日边界：用户本地时间 **04:00**。00:30 学习算"昨天"，避免熬夜用户被跨天惩罚。
- `due_on` 存用户本地日期（`DATE`），同时存 `timezone`；服务端按用户时区计算"今天"。
- 跨时区旅行：以用户当前时区为准，历史 `due_on` 不重算；出现"负延迟"时按当天到期处理。
- 补复习：`due_on < 今天` 的词全部进入队列，按 3.4 排序；不因逾期额外惩罚间隔（逾期本身已经是复习延迟）。
- 离线：客户端缓存队列并记录本地作答；恢复网络后按顺序补交，服务端幂等重放（见 8.5）。

## 4. 单词即行动

### 4.1 三种行动卡

每个词在词表中必须绑定一种 `card_type`，并配一个 `effect_tag`。类型不改变判定方式（都是"回忆英文"），只改变剧情表现和失败叙述。

| 类型 | 对应词性/语义 | 典型效果 | 示例 |
| --- | --- | --- | --- |
| **法术**（spell） | 动词、抽象名词 | 护盾、照明、点燃、揭示、加速 | `barrier` 屏障 → 挡下一次伤害 |
| **道具**（item） | 具体名词 | 回复、开路、交换、保存、指路 | `compass` 指南针 → 指出正确岔路 |
| **检定**（check） | 形容词、副词、部分动词 | 观察、判断、说服、潜行、抵抗 | `fragile` 脆弱的 → 发现石桥裂缝 |

`effect_tag` 建议枚举（MVP 够用）：

```text
shield, damage, heal, reveal, traverse, persuade, hide, detect, restore, delay
```

每个词只能有一个主 `effect_tag`；内容管线负责去重和配平，避免全章都是 `shield`。

### 4.2 一次行动如何结算

```text
场景旁白
  → 出现 1–2 个可选行动（每个行动绑定一张词卡；卡面只显示中文语义 + 效果，不显示英文）
  → 玩家选择一个行动（或选"硬闯"）
  → 系统提示："说出/输入这张卡的英文"
  → 玩家提交
      ├─ 正确：播放成功文本，结算效果
      └─ 错误/超时：播放失败文本，结算 HP/线索/分支，SRS 回到 1 天
  → 进入下一拍或下一场景
```

关键规则：

- **卡面绝不显示英文单词**，只显示中文语义和效果。否则"选卡"变成"抄答案"。
- 每个行动槽绑定一个 `target_word`（服务端持有英文答案）；客户端只拿到中文提示、效果和选项 id。
- 场景提供 2 个行动时，玩家选 1 个执行；另一个不结算，可在章节重玩/复盘时尝试。场景只要求"这一拍至少成功一次"，失败则进入代价分支。
- 如果玩家一个词也想不起来：提供"硬闯"——不测试单词，直接支付固定代价（HP -15 或线索 -1），保证永不软锁。
- 同一词在同一场景最多出现 1 次；同一天最多进入 2 个行动槽（运行时校验）。
- `known` 词不进入普通词行动（只在 BOSS 抽查中出现）。若某行动的目标词被该用户标记为 `known`，客户端自动替换为同场景另一个未 known 的词；无可用词时显示"硬闯"。
- 每次行动提交都必须带 `idempotency_key`，防止重复扣血/重复加进度。

### 4.3 失败代价：HP、线索、分支

每个行动在内容里必须声明一种失败代价，三选一：

| 代价 | 数值 | 表现 | 恢复方式 |
| --- | --- | --- | --- |
| **HP** | 10 / 15 / 20（按难度） | 受伤、被击退、护盾碎裂 | 场景"喘息" +20；章节开始 100；上限 100 |
| **线索** | -1 条（每章最多可获得 3 条，最低 0） | 错过脚印、地图被毁、NPC 不再信任 | 该词累计正确 3 次（含补测/顽固词小练/剧情行动），可找回（不限天数） |
| **分支** | 进入代价剧情 | 走暗道、错过集市、被守卫盯上 | 可用"重掷"改写一次；或后续剧情修复 |

**力竭规则**：HP ≤ 0 时不删档、不回档：

1. 本章 HP 置为 50；
2. 失去 1 条线索（若无线索则改为下一场景失败代价翻倍）；
3. 当前场景从最近一个"行动结算点"重开，已成功的行动保留；
4. 玩家可继续，不强制退出。

**失败前进（fail-forward）**：任何失败都必须返回一个可继续的 `next` 场景/节拍；禁止出现"答错就卡死在当前场景"。分支可以更差，但不能是死路。

**重掷**：每连续 7 天完成每日目标获得 1 枚，最多存 2 枚；可在失败结算时使用，允许改用同一场景的另一个行动重试一次（SRS 的失败记录不回滚，剧情代价可免）。

### 4.4 数值与平衡

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| 每章初始 HP | 100 | 每章独立，不跨章累积 |
| 失败伤害 | 10 / 15 / 20 | 难度 1/2/3 |
| 喘息恢复 | +20 | 每章 2 次，出现在固定场景 |
| 线索 | 每章最多可获得 3 条 | 影响支线、结局文本，不影响主线通行 |
| BOSS 检定数 | 5 | 成功 ≥3 即"净化"；失败可继续 |
| BOSS 失败伤害 | 20 | 力竭则撤退，下一章以 HP 70 开始 |
| 重掷 | 最多 2 枚 | 7 天连续完成 +1 |
| 经验 | +10/次成功行动 | 仅用于展示"词力等级"，不构成数值门槛 |
| 跳过词经验 | 0 | 防止为经验而跳过 |

平衡原则：

- 一章正常失败 3–6 次是设计区间；超过 8 次说明词太难或提示不足，内容需要调整。
- HP 不是核心资源，**失败的学习代价（回 1 天）比 HP 更重要**；HP 只负责"有感觉"。
- 不允许"花钱复活""看广告回血"；MVP 无商业化。

### 4.5 新词契约

每天的新词在剧情中以"词灵契约"出现，每个词 15–25 秒：

1. 展示：英文 + 音标 + 中文 + 一个 ≤12 词的例句（中文翻译可折叠）。
2. 立即小测：看英文，4 选 1 中文（或听音选义）。
3. 答对：契约通过，正常进入场景；答错：显示正确答案，不额外扣 HP，但若该词出现在随后的场景行动中会被补测一次，SRS 仍为 1 天。
4. 契约结束才进入该场景的旁白和词行动。

> 契约本身就是一次测试，不存在"只读一遍就过"的环节。

### 4.6 遭遇数据结构与示例

```json
{
  "id": "ch1_sc03",
  "chapter": 1,
  "order": 3,
  "title": "落石走廊",
  "narration": "雾港的旧矿道在脚下发颤。碎石从头顶落下，前方只剩一道半塌的石门。",
  "featured_words": ["avoid", "balance"],
  "actions": [
    {
      "id": "a1",
      "prompt": "落石砸下。你想起那道闪避咒语——「避开」。",
      "target_word": "avoid",
      "card_type": "spell",
      "difficulty": 2,
      "success": {
        "text": "你侧身滚进石缝，碎石擦着后背飞过。",
        "effect": { "type": "avoid_damage" }
      },
      "failure": {
        "text": "咒语卡在喉咙里。石块擦过肩膀，你踉跄着冲进门缝。",
        "cost": { "type": "hp", "amount": 15 }
      }
    },
    {
      "id": "a2",
      "prompt": "石门后的栈道只剩一根横木。你需要稳住重心——「平衡」。",
      "target_word": "balance",
      "card_type": "check",
      "difficulty": 2,
      "success": {
        "text": "你张开双臂，踩着横木挪到对岸。",
        "effect": { "type": "reveal", "clue": 1 }
      },
      "failure": {
        "text": "你脚下一滑，抓住藤蔓才没掉下去。墙上的刻字被雾遮住了。",

      }
    }

```

字段说明：

- `featured_words`：本场景必须覆盖的词；内容校验要求每词至少出现在一个场景的 `featured_words` 中。
- `actions[].target_word`：服务端持有，客户端不可见英文答案。
- `failure.cost.type`：`hp | clue | branch`；`branch` 时 `failure.next` 指向代价分支场景。
- `narration` ≤ 120 个汉字；`prompt` ≤ 60 个汉字；`success.text` / `failure.text` ≤ 80 个汉字。
- `effect_tag` 是词的能力标签（如 `shield`）；`success.effect.type` 是服务端结算指令（如 `avoid_damage`、`reveal`），两者不要混用。

### 4.7 防答案泄露与防作弊

- 卡面只显示中文语义和效果；英文在提交后才揭示。
- 复习选项由服务端生成，干扰项从同章、同词性、同长度词中抽取，避免"一眼排除"。
- 客户端不缓存 `target_word` 的英文；所有判定在服务端完成。
- 打字判定：忽略大小写、首尾空格、连续空格；不允许"只输入首字母"；拼写错误即失败，但显示 diff 高亮。
- 自评模式（说出口后点"说对了"）只作为无障碍备选，MVP 默认打字；自评结果同样进入 SRS，但标记 `self_graded` 供分析。
- 同一词在同一天最多被剧情测试 2 次；超过则改用其他 `featured_words`，避免刷分。
- 已认识跳过必须验证，不允许"一键全跳"。

### 4.8 内容规范（词行动）

- 每个场景至少 1 次词行动，最多 2 次；没有词行动的场景直接砍掉。
- 每个行动必须能一句话说清"为什么这个词能解决这个问题"；说不清就换词或换场景。
- 失败文本必须写"代价"，不能只写"你失败了"；成功文本必须写"效果"，不能只写"你成功了"。
- 不允许连续 3 个场景使用同一主 `effect_tag`；不允许 BOSS 前连续 5 次 `hp` 失败。
- 每个词的行动必须与词义强相关；禁止"用 `apple` 当护盾"这类纯占位。

### 5.2 素材与词表构建管线

本文的"词频"指：**在 CET-4 大纲词范围内，用需求方提供的四级真题素材统计出的加权出现频次**；不是字母序、教材单元序，也不是通用语料频次。素材试跑见附录 E。

**已提供素材**（24 个可见文件，其中 2 个六级文件不纳入）：

| 类别 | 素材 | 用途 | 约束 |
| --- | --- | --- | --- |
| 真题主语料 | 2019–2025 年 CET-4 真题/解析 PDF（2023-12、2024-06/12、2025-06/12、2019-06/12 等） | 统计词频、筛例句候选 | 只取英文正文；排除答案、解析、中文译文、题干选项 |
| 核心词先验 | 《四级英语核心词 艾宾浩斯抗遗忘打卡》 | 校验 288 词覆盖率、补充候选 | 不直接拿它的顺序当词频 |
| 补充语料 | 《就这样过英语四级》《英语四级 你还在背单词吗》《自我评测卷》《刷题冲刺卷》 | 补充例句、覆盖低频大纲词 | 不参与主词频；模拟题不得压过真题高频词 |
| 范围校验 | CET-4 考试大纲词汇表 | 最终词必须在大纲内 | 版权/授权需复核 |

- **不纳入**：两个六级 PDF（`六级2019-6-1/2`），避免六级词污染四级词表。
- **版权**：原始 PDF 不提交到仓库，不复制长段原文；仓库只存派生数据（lemma、加权频次、章节号）和原创例句。
- **可复现**：素材版本、文件哈希、抽取脚本、停用词表、词形还原词典记录在 `content/SOURCES.md`；换素材必须重新生成词表并跑校验。

**处理步骤**：

1. **抽取**：优先读取 PDF 的 ABBYY 文本层；无文本层再 OCR。按页/题型切分，只保留英文正文（写作、听力原文、阅读、翻译），排除答案、解析、中文译文、页眉页脚。
2. **还原**：OCR 会把字母拆开（如 `H a v e` → `Have`），先做 detokenize；统一小写，处理连字符、所有格、缩写。
3. **过滤**：去停用词、数字、中文、专有名词、题干选项标记（A/B/C/D）、页眉页脚、乱码；只保留 CET-4 大纲内词。
4. **还原词形**：lemmatize（running→run、studies→study），按 lemma 计数；同形异义按大纲主词性合并。
5. **加权**：只对真题加权：2023 年及以后 1.0，2019–2022 0.7；同一篇内每词最多计 3 次。补充语料不参与 `score`，只用于选例句/补低频词。
6. **排序**：`score = 加权真题频次`；同分按"核心词表顺序 → 近 3 年出现次数 → 字母序"。
7. **取数**：过滤后取前 288；按 48 个连续切块，第 n 块即第 n 章。
8. **绑定行动/写场景/校验**：见 5.7 与 8.6 校验脚本；不通过不发布。

**排序验收**：

- `freq_rank` 必须唯一且连续（1–288）。
- 任意 `freq_rank` 更小的词，必须出现在更早的章/更早的场景。
- 章内新词发放顺序必须与 `freq_rank` 升序一致。
- 288 词必须全部落在 CET-4 大纲内；核心词表覆盖率目标 ≥90%，未覆盖词需人工复核；六级词、超纲词、专有名词为 0。
- 用附录 E 的试跑脚本可复现；换素材必须改版本号并重跑。

### 5.3 章节内节奏（默认 12 词/天）

| 天 | 场景 | 新词 | 内容 |
| --- | --- | --- | --- |
| 第 1 天 | 场景 1–3 | 1–12 | 进入章节、认识核心冲突、第一次失败代价 |
| 第 2 天 | 场景 4–6 | 13–24 | 探索、一次分支选择 |
| 第 3 天 | 场景 7–9 | 25–36 | 线索收集、代价升级 |
| 第 4 天 | 场景 10–12 | 37–48 | BOSS 前夜、BOSS 战、章节结算 |

- 每章固定 2 次"喘息"（+20 HP），并至少有 1 次"线索"获得机会。
- 每章至少 2 个分支点；分支不改变词序，只改变叙述、线索和后续代价。
- 章节结束条件：48 词全部契约（含 known）+ BOSS 已尝试（成功或撤退）。满足即解锁下一章。
- BOSS 失败不阻止进入下一章：下一章以 HP 70、少 1 条线索开始，剧情中给出"撤退"叙述；玩家可回看旧章 BOSS 进行"净化"（仅影响成就和线索）。

### 5.5 BOSS 设计

BOSS 是章节收束，不是数值墙。

- **结构**：5 个词检定，来自本章不同场景；至少 1 个来自最近 3 天；若本章存在 `lapses >= 2` 的词，至少抽 1 个。
- **胜利**：成功 ≥3 次 → "净化"章节，获得 1 条线索 + 章节结算文本。
- **失败**：仍可继续；HP -20/次失败；HP ≤0 触发撤退（见 4.3）。撤退后下一章以 HP 70 开始，并少 1 条线索。
- **已知词抽查**：若本章有 ≥5 个 `known` 词，BOSS 额外抽 1 个做"封印确认"；失败只重开该词，不扣 HP。
- **可重玩**：章节结算后可在"词境地图"重打 BOSS，用于拿回线索/成就；重打不重复发新词。
- **时间**：BOSS 控制在 2–3 分钟，不超过 5 个检定 + 2 段旁白。

### 5.6 章节解锁与扩展

- 解锁条件：本章 48 词全部契约 + BOSS 已尝试。
- 解锁后，旧章仍可进入复习/重打 BOSS，但不再发新词。
- **第二季**：继续取 289–576 名，做 6 章新词包；核心循环、SRS、UI 完全复用，只换内容。不在 MVP 范围。
- **不做的扩展**：每日一词挑战、付费词包、广告解锁——MVP 不引入会破坏核心循环节奏的系统。

### 5.7 每章制作清单

- [ ] 48 个词按 `freq_rank` 排序，无重复、无缺词。
- [ ] 12 个场景，每场景 4 词，全部覆盖。
- [ ] 每场景 ≥1 次词行动，≤2 次；行动与词义强相关。
- [ ] 每场景旁白 ≤120 字，行动提示 ≤60 字。
- [ ] 至少 2 个分支点、2 次喘息、1 次线索机会。
- [ ] BOSS 5 检定；有顽固词时必含 1 个。
- [ ] 失败文本都写了具体代价，成功文本都写了具体效果。
- [ ] 跑通 8.6 校验脚本和 10.3 验收清单。

## 6. 可持续机制

### 6.1 固定习惯锚点

首次进入时只问两个问题：

1. "你最容易在什么时候学？" → 起床后 / 通勤 / 午休 / 睡前。
2. "大概几点？" → 时间选择器。

系统行为：

- 保存 `anchor_type` + `anchor_time` + `timezone`。
- 在锚点时间发送本地通知；文案绑定具体场景，例如："雾港的摆渡人还在等你。今天只需 5 分钟复习。"
- 锚点后 2 小时未打开，发第二条温和提醒；每天最多 2 条；23:00–07:00 静默。
- 支持随时改锚点；连续 3 天在锚点 ±30 分钟内完成，显示"锚点已稳固"。
- **2 分钟微会话**：通知里可直接选"只复习 10 张"，保留 streak，不推进剧情。

### 6.2 进度可见

首页必须在一屏内回答四个问题：

1. 我今天要做什么？→ 复习 X 张 / 新词 Y 个 / 剧情目标。
2. 我坚持了多久？→ streak、本周完成天数。
3. 我走到哪了？→ 6 章地图、当前场景、章节进度条。
4. 我记住了多少？→ 已掌握 / 复习中 / 已认识 / 顽固词数量。

具体元素：

- **今日环**：三段进度（复习、新词、剧情），完成一段点亮一段。
- **章节地图**：6 个节点，当前节点高亮；已净化章节显示不同图标。
- **词力面板**：`mastered` 数量为主指标；`known` 单独显示，不计入掌握。
- **复习到期数**：首页常驻；>65 时变成橙色提示。
- **词书**：按章/状态/到期日筛选；每个词显示下次间隔（1/3/7/16 天）、下次到期、错误次数。
- **周报**：每周日生成；包含复习量、正确率、新词数、章节进度、下周建议；可分享。

### 6.3 异步与社交

MVP 只做异步，不做实时：

1. **战报分享**：结算页生成一张文字卡（章节、streak、复习数、正确率、今日关键词、一个剧情选择），可保存图片/复制链接。默认不展示完整词表，用户可勾选。
2. **挑战码**：用户选 10 个词（默认今日新词）生成 6 位码；好友输入码后先看这 10 个词的契约卡，再玩 3 个短场景，按"正确数 + 用时"得到异步成绩。挑战不计入对方 SRS/章节进度，双方各自收到对比结果，不需要同时在线。
3. **小队周目标**：3–5 人组成小队，周目标为"全队累计复习 500 张"；只显示团队进度条，不显示个人排名，避免焦虑。达成后全队获得装饰性徽章。
4. **路标留言**：每章结束可留一条**预置文案**（"这里的雾会骗人"等），好友经过时看到；MVP 用预置选项，不做自由文本，规避审核成本。

社交原则：

- 社交是"异步陪伴"，不是"必须组队"；单人玩家不受任何惩罚。
- 不展示好友的生词列表、错误记录、HP 等隐私数据。
- 推送只推"小队目标达成/好友挑战"，不推"好友超过你"。

### 6.4 "已认识"跳过（产品入口）

- 位置：新词契约卡右下角"我已认识"。
- 流程：点击 → 随机验证 1 题 → 通过则跳过，失败则正常学习。
- 反馈：通过后显示"已移入已认识，不计入掌握，可在词书撤销"。
- 词书：`known` 筛选页，可单个撤销；撤销后 `state = review`，`stage 0`，`due = 明天`。
- 数据：跳过率按章统计；某章跳过率 >35% 时，内容团队要检查该章是否过难或词频失真。

### 6.5 断签与回归

- **打卡**：完成"复习到期清空 + 至少 1 个剧情场景"即算当日完成。
- **保底**：复习 ≥10 张（约 2 分钟），或清空全部到期（到期不足 10 张时）算保底，保留 streak，但不发"完成"奖励。
- **休整券**：每月自动发 2 张，断签时自动使用，保留 streak；不补复习欠账。
- **回归**：≥3 天未学，给"回归任务"：复习 20 张 → 恢复 1 条线索 / +20 HP；当天新词降为 10；不要求补完所有逾期。
- **断签不清空**：等级、词库、章节、已掌握词永不因断签清零。

### 6.6 通知策略

| 类型 | 触发 | 频率 | 示例文案 |
| --- | --- | --- | --- |
| 锚点提醒 | 每日锚点时间 | 1 次 | "咖啡好了。雾港的摆渡人只等你 5 分钟。" |
| 二次提醒 | 锚点 +2h 未打开 | 1 次 | "今天 12 个词，3 个场景，15 分钟就能收工。" |
| 复习堆积 | 到期 > 65 | 最多 1 次/天 | "记忆神殿积了 70 张卡，先清 10 张也算数。" |
| 小队 | 周目标达成/差一点 | 最多 1 次/天 | "小队还差 40 张复习，今晚一起收个尾？" |
| 回归 | ≥3 天未打开 | 第 3 天 1 次 | "词境还在，进度也还在。回来做 10 张就好。" |

- 所有通知可分类关闭；关闭不影响学习。
- 不在 23:00–07:00 发送。
- 不使用"你再不来就前功尽弃"这类焦虑文案。

## 7. 要避开的坑

### 7.1 一次背太多

**症状**：单日新词 30+、一次 30 分钟、第二天大量遗忘、直接弃坑。

**设计对策**：

- 新词硬上限 20/天，默认 12；没有"无限模式"；原型档 0–4 个演示词是独立会话，不写正式进度。
- 复习优先：复习没清完，新词锁定。
- 到期 >65 时主动建议降到 10；>85 时默认只复习。
- 默认档按 4 词/场景、3 场景/天切好，用户不需要自己决定"今天背多少"。
- 设置页不提供"一次背 100 个"的入口；导入词表也只能进入"待学队列"，不能插队到今日。

**验收**：任意路径下，单日新词数不可能超过 20；复习未清空时新词不发放、不可用。

### 7.2 只读不测

**症状**：看释义、看例句、翻卡点"认识"，从不主动回忆；考试时想不起来。

**设计对策**：

- 新词契约 = 展示后立刻小测，答完才算契约完成。
- 复习 = 先出题后出答案；没有"翻卡即完成"。
- 剧情 = 必须输入/说出英文才能生效；没有"看答案过关"。
- 统计 `firstTryAccuracy`：新词契约正确率 >95% 说明选项泄露/太简单；<50% 说明太难，内容要调。
- 不设"阅读模式"给进度；听例句、看词根只是辅助，不计入学习。

**验收**：任何一个词要进入 `review`，必须至少完成 1 次提交；不存在纯浏览加进度的路径。

### 7.3 没有复习

**症状**：每天学新词很爽，旧词从不回顾；7 天后等于没学。

**设计对策**：

- 复习块永远排在剧情前；不清空不发放新词。
- streak 与"复习到期清空"绑定；只做剧情不算完成。
- 首页常驻到期数；积压变橙。
- 每周周报显示"按时复习率"和"逾期最多"的词。
- 剧情行动只使用本章已契约的词；未契约词不会出现在行动槽里。复习只决定"什么时候再测"，不阻塞剧情使用。
- 逾期不惩罚间隔，但逾期词会排在队首，优先清理。

**验收**：`due` 未清空时 `/story/next` 返回 409 或锁定态；不存在绕过复习直接刷剧情的 API。

### 7.4 剧情过重

**症状**：大段设定、专有名词、过场不能跳；玩家读剧情 10 分钟，背词 2 分钟。

**设计对策**：

- **词为剧情服务**：先有当天要学的词，再写场景；没有词的场景砍掉。
- 文本预算：场景旁白 ≤120 字，提示 ≤60 字，成功/失败文本 ≤80 字；每天剧情文本总量 ≤800 字。
- 词行动时间 ≥剧情总时长的 60%；每场景至少 1 次词行动。
- 过场可跳过/倍速；设定信息放进"线索卡"，不强制阅读。
- 每章新 NPC ≤3 个；不造生僻专有名词；不用大段世界观解释。
- 剧情跳过率 >30% 时，内容团队必须重写该章。

**验收**：随机抽 3 个场景，词行动时间占比 ≥60%；所有旁白可一键跳过；无场景纯阅读超过 30 秒。

### 7.5 失败卡关 / 惩罚过重（补充）

- 失败必须 fail-forward；任何 `failure` 都要有 `next`。
- HP 归零不删档；线索丢失可找回；章节不重置。
- BOSS 失败也能进下一章，只是带代价。
- 不用"体力值/生命值买体力"阻止继续学习。

### 7.6 上线前检查清单

- [ ] 单日新词 ≤20，默认 12；复习未清空时新词锁定。
- [ ] 新词契约 100% 有即时小测；复习 100% 先题后答。
- [ ] 1/3/7/16 调度单测全部通过；答错回 1 天。
- [ ] 剧情每次行动都能失败前进；HP/线索/分支代价都有文案。
- [ ] 6 章 × 48 词，词频严格递增，章内顺序正确。
- [ ] 3 个"已认识"验证路径都能跑通；BOSS 抽查可重开。
- [ ] 首页能一屏看到 streak、章节、到期数、掌握数。
- [ ] 锚点通知、2 分钟微会话、休整券可用。
- [ ] 分享卡/挑战码不泄露隐私；小队不展示个人排名。
- [ ] 标准档（15 分钟）实测 13–17 分钟；超过档位预算 5 分钟有结束提示。

### 8.1 架构

```text
┌────────────────────┐      HTTPS/JSON      ┌────────────────────┐

                                                     │

                                                     │
                                           ┌─────────▼──────────┐
                                           │ 内容 JSON（版本化）   │

                                           └────────────────────┘
```

- 客户端：移动优先的 PWA（React/Next.js）或小程序；文字 + 图标 + 少量插画。MVP 先做 PWA，避免双端。
- 服务端：Node/TypeScript + PostgreSQL；SRS、HP、线索、进度全部服务端权威。
- 内容：`content/words.json`、`content/scenes/ch1.json`…，随代码版本化；CDN 静态分发，服务端只存 id 和进度。
- 鉴权：设备匿名 token 起步；可绑定手机号/邮箱做云同步。MVP 不强制登录。
- 实时：不需要；挑战码/小队用轮询或下次打开时拉取。

约束：

- `user_words.stage` 与 `due_on` 只能由服务端调度函数写入；客户端提交答案，不提交日期。

- 所有"答题"接口必须有 `idempotency_key`，唯一索引 `(user_id, idempotency_key)`。
- 场景/行动的完整内容（`actions` / `choices` / `success` / `failure`）以 `content/scenes/*.json` 为准；`scenes` 表只做索引与校验，可由构建脚本生成。

### 8.4 关键算法伪代码

**复习提交**：

```ts
async function submitReview(userId, sessionId, wordId, answer, idemKey) {
  return db.transaction(async (tx) => {
    const prev = await tx.reviewEvents.findByKey(userId, idemKey);
    if (prev) return prev.result;                    // 幂等

    const word = await tx.words.get(wordId);
    const user = await tx.users.get(userId);
    const correct = isReviewAnswerCorrect(word, answer, reviewMode); // 选择题比对选项；拼写模式比对 lemma
    const today = learningDay(user.timezone);

    await tx.userWords.lock(userId, wordId);
    const uw = await tx.userWords.get(userId, wordId);
    review(uw, correct, today);                      // 见 3.3
    await tx.userWords.save(uw);
    await tx.reviewEvents.insert({...});

    return { correct, correctAnswer: word.lemma, nextDueOn: uw.dueOn, ... };
  });
}
```

**剧情行动**：

```ts
async function submitStoryAction(userId, sessionId, sceneId, actionId, answer, idemKey) {
  return db.transaction(async (tx) => {
    const prev = await tx.storyEvents.findByKey(userId, idemKey);
    if (prev) return prev.result;

    const action = await tx.content.getAction(sceneId, actionId);
    const correct = normalize(answer) === action.targetWord.lemma;
    const uw = await tx.userWords.get(userId, action.targetWord.id);
    const today = learningDay(user.timezone);
    if (!uw || uw.state === 'known') throw new Error('WORD_NOT_INTRODUCED');

    if (correct) {
      applyEffect(action.success.effect, tx);
    } else {
      review(uw, false, today);                       // 失败 = SRS 回 1 天
      applyCost(action.failure.cost, tx);             // HP/线索/分支
    }
    await tx.userWords.save(uw);
    await tx.storyEvents.insert({...});
    return { correct, effect: correct ? action.success : null, cost: correct ? null : action.failure.cost };
  });
}
```

**每日结算**：

```ts
async function finishSession(userId, sessionId) {
  const s = await getSession(sessionId);
  if (s.tier === 'prototype') return finishPrototype(sessionId); // 不写正式进度
  const reviewed = await countReviewEvents(sessionId);
  const scenes = await countCompletedScenes(sessionId);
  const reviewCleared = s.due_count === 0 || s.review_completed_at != null;
  if (reviewCleared && scenes >= 1) markDailyComplete(userId);   // 完成
  else if (reviewCleared || reviewed >= 10) markMinimum(userId); // 保底，保留 streak
  await updateProgress(userId);
  await buildTomorrowPreview(userId);
}
```

### 8.5 同步、离线与幂等

- 客户端只缓存"已下发的题目 + 用户答案"，不缓存 `target_word` 的英文答案（剧情行动由服务端判分）。
- 离线复习：本地按队列作答，恢复网络后逐条提交；每条带 `idempotency_key = sessionId:wordId:attempt`。
- 服务端重放顺序必须与本地一致；若某条冲突（例如会话已结束），返回上次结果，不重复扣血。
- 多设备：同一账号以服务端为准；客户端启动时拉取最新 `user_words` 和 `user_progress`。
- 时钟：所有日期计算以服务端 + 用户时区为准；客户端只显示，不参与 `due_on` 计算。

### 8.6 内容管线与校验

目录建议：

```text
content/
  words.json
  chapters/ch1.json ... ch6.json
  scenes/ch1_sc01.json ...
  schemas/word.schema.json
  schemas/scene.schema.json
scripts/
  extract-exams.ts       # 从真题 PDF 抽取英文正文
  build-wordlist.ts      # 从抽取结果生成 words.json
  validate-content.ts    # 发布前校验
```

`validate-content.ts` 必须检查：

1. 6 章、每章 30–50 词、总词数 288（MVP）。
2. `freq_rank` 唯一、连续；章内顺序与 `freq_rank` 升序一致。
3. 每章 12 场景、每场景 4 词、`featured_words` 覆盖全章词。
4. 每个词有 `card_type` / `effect_tag` / `difficulty` / `failure_cost`，且 `failure_cost ∈ {hp, clue, branch}`。
5. 每个场景 1–2 个 `action`，`target_word` 必须属于 `featured_words`。
6. 文本长度：旁白 ≤120 字，提示 ≤60 字，成功/失败 ≤80 字。
7. 每个 `failure` 都能落到下一拍（fail-forward）；`failure.cost.type = branch` 时 `failure.next` 必填。
8. 无重复 `id`；无非法字符；音标字段非空。
9. 每章至少 2 个分支点、2 次喘息、1 次线索机会。
10. 行动类型/效果配平：同章连续 3 个场景不得使用同一主 `effect_tag`。

校验不通过 → CI 失败 → 不允许发布。

- 遵守未成年人保护要求；MVP 不面向 14 岁以下。

## 9. 内容制作规范

### 9.1 词卡字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `id` | 是 | `w_<lemma>`，唯一 |
| `lemma` | 是 | 小写，词形还原后的原形 |
| `ipa` | 是 | 英式或美式统一一种，全库一致 |
| `pos` | 是 | `n. / v. / adj. / adv. / prep. / conj.` |
| `meanings` | 是 | 1–2 个 CET-4 核心义；中文，分号分隔 |
| `example_en` | 是 | ≤12 词，包含目标词，不使用超纲词 |
| `example_zh` | 是 | 与英文例句一一对应 |
| `freq_rank` | 是 | 1–288，由管线生成 |
| `chapter` | 是 | 1–6，由 `freq_rank` 推导，不允许手填 |
| `card_type` | 是 | `spell / item / check` |
| `effect_tag` | 是 | 枚举值，见 4.1 |
| `effect_text` | 是 | ≤20 字，说清"这个词能做什么" |
| `difficulty` | 是 | 1–3，按词长/抽象度/易混度评估 |
| `failure_cost` | 是 | 词的默认代价类型：`hp / clue / branch`；场景行动可覆盖，最终以行动配置为准 |
| `audio_url` | 否 | TTS 或录音；MVP 可先用系统 TTS |

### 9.3 文案风格

- 第二人称"你"，短句，避免翻译腔。
- 不写大段世界观；设定通过动作和代价透露。
- 失败文本不羞辱玩家："手一抖""咒语卡在喉咙里"，而不是"你怎么这么笨"。
- 成功文本给具体画面，不给空泛的"你成功了"。
- 每章最多 3 个 NPC；NPC 名字用常见中文名/称号，不造生僻词。
- 所有英文例句必须包含目标词，且不引入未学的高难词。

### 9.4 评审清单

- [ ] 这个词为什么能解决这个场景的问题？一句话能说清。
- [ ] 卡面只显示中文，英文是否泄露？
- [ ] 失败代价是否具体、可结算、不阻断？
- [ ] 场景是否 ≤120 字？是否有可跳过选项？
- [ ] 是否覆盖了本组 4 个词？是否有词被硬塞？
- [ ] 连续场景是否重复同一效果类型？
- [ ] 是否引入了新的专有名词/设定负担？

## 10. MVP、里程碑与验收

### 10.1 MVP 范围

**必须有**：

- 288 词、6 章、12 场景/章。
- 会话档位：5–8 分钟原型档、10–13 分钟轻量档、15 分钟标准档、17–18 分钟加速档、20 分钟深度档。
- 每日会话：复习 → 剧情 → 结算。
- 1/3/7/16 SRS、复习优先、新词 10–20。
- 词行动（法术/道具/检定）、HP/线索/分支失败代价、fail-forward。
- 已认识跳过 + 验证 + BOSS 抽查。
- 习惯锚点、2 分钟微会话、streak、休整券。
- 首页进度、章节地图、词书。
- 战报分享、挑战码、小队周目标（异步）。
- 内容校验脚本 + 关键单测。

**可以后置**：

- 账号云同步（先设备 token）。
- 语音自评、发音评分。
- 更多词包/第二季。
- 成就系统、装饰性皮肤。
- 多语言 UI。

**明确不做**：

- 实时 PVP、公会战、排行榜。
- 付费/广告复活。
- 用户自由文本社交。

（工期为 1 名全栈 + 1 名内容 + 兼职设计的估算，可按团队规模缩放。）

### 10.3 验收标准

**A. 循环**

- [ ] 标准档（12 新词）实测 13–17 分钟；复习 ≤5 分钟、剧情 ≤10 分钟。
- [ ] 轻量档（10 新词）10–13 分钟；加速档（15 新词）17–18 分钟；深度档（20 新词）约 20 分钟；原型档（0–4 演示词）5–8 分钟且不写正式进度。
- [ ] 任意一天，复习未清空时无法进入剧情（API 返回 409）。
- [ ] 单日新词数不可能 >20；默认 12；正式档设置只允许 10/12/15/20；原型档 0–4 为独立演示会话。

**B. SRS**

- [ ] 3.9 的 15 条用例全部通过。
- [ ] 答错后 `stage = 0`、`due = 明天`，无例外。
- [ ] 16 天封顶，不会出现 32 天。
- [ ] 剧情失败会回 1 天；剧情成功不改变排期。

**C. 词行动**

- [ ] 每次词行动（"硬闯"除外）都必须提交英文；卡面不出现英文。
- [ ] 失败必定结算 HP/线索/分支之一，并继续到下一拍。
- [ ] HP 归零不删档、不回档、不卡关。
- [ ] 想不起单词时"硬闯"可用。

**D. 章节**

- [ ] 6 章 × 48 词，每章 30–50。
- [ ] `freq_rank` 1–288 连续，章内严格升序。
- [ ] 正式档每场景 4 词，12 场景/章，每词至少 1 次契约；原型档 2–4 个演示词/场景。
- [ ] BOSS 5 检定，失败可进下一章。

**E. 留存/社交**

- [ ] 锚点可设置、可改、通知可关。
- [ ] 2 分钟微会话可保留 streak。
- [ ] 首页一屏可见 streak、章节、到期、掌握。
- [ ] 战报/挑战码/小队可用且不泄露隐私。
- [ ] 已认识验证通过/失败/撤销/BOSS 抽查全路径可用。

**F. 内容**

- [ ] 8.6 校验脚本在 CI 通过。
- [ ] 抽检 10 个场景：词义匹配、失败代价具体、无纯阅读超 30 秒。
- [ ] 抽检 10 个词：例句含目标词、释义为 CET-4 核心义、无超纲例句。

### 10.4 指标与风险

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 内容成本高 | 288 词 × 场景写作慢 | 模板化场景、每场景 4 词、先写 1 章试玩再批量 |
| 复习疲劳 | 到期多、5 分钟做不完 | 快速/冲刺模式、复习优先日、积压提醒 |
| 剧情仍过重 | 跳过率高、时长超 | 文本预算、词行动占比、可跳过、周报监控 |
| 跳过滥用 | 已认识率异常高 | 验证题、BOSS 抽查、跳过率分章监控 |
| 难度失衡 | 单章失败 >8 次 | 按章统计失败率，调 `difficulty`/提示 |
| 标准档时长守不住 | 深度档拖到 25 分钟 | 设置页显示预计时长、超过档位预算 5 分钟强制收尾提示 |
| 词频数据争议 | 用户觉得"这词不常考" | 公开词表来源与排序口径；接受反馈但不逐条改序 |

### 10.5 待验证假设（不阻塞开发）

1. 12 词/天是否比 10 词/天更能坚持——内测 A/B。
2. 剧情失败回 1 天是否惩罚过重——观察失败后 3 天留存。
3. "已认识"验证 1 题是否足够——观察 BOSS 抽查失败率。
4. 挑战码是否有人用——观察分享→挑战转化率。

### E.2 试跑记录（2023-12 第 1 套）

对《2023年12月第1套英语四级真题解析.pdf》（19 页）做一次管线试跑：

- **文本层可用**：ABBYY 文本层能直接抽取，无需重新 OCR。
- **抽取结果**：约 79,000 字符；未清洗英文 token 约 2,972 个。
- **观察 1**：字母被空格拆开（`H a v e`），必须做 detokenize；否则词频全是单字母。
- **观察 2**：解析/答案区会带进 `section`、`adj`、人名（如 Alan）等噪声；必须先按题型分区，只统计英文正文。
- **观察 3**：单套题的高频词偏主题化（试跑中 food/diet/healthy 靠前），不能直接当 288 词全表；必须跨 15 份真题汇总。
- **结论**：素材可用，但**不能跳过清洗直接统计**；5.2 的抽取/过滤/加权步骤是必须的。

### E.3 复现要求

- 每次换素材或改权重，必须重跑 8.6 校验，并在 PR 中附"词表版本 + 覆盖统计"。
