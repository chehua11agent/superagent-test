# 剧情 → 词卡战斗 → 复习：可组合故事单元

> 状态：**MVP 已接入第 4 幕**（3 回合、4 张词卡、认出/拼出双检定）；牌库组合、条件/flag、多场战斗、BOSS 卡牌化尚未接入。
> 目标：让**同一个词**先在事件剧情里出现，再在战斗阶段变成可打的卡牌，最后回到复习队列；剧情负责用法，战斗负责反复取用，SRS 负责长期记住。

## 1. 现在的断点

当前《雾港》的循环是：

```text
词灵契约（认义） → 剧情旁白 → 1–2 次词行动（拼写） → 结算 → 复习
```

词行动本身已经是一张“卡”：有中文语义、效果、难度和失败代价。但它是一次性的：

- 战斗/对抗只有一个行动槽，没有手牌、回合、敌人意图；
- 同一个词在剧情里出现后，下一幕不一定再用；
- BOSS 是五道问答题，不是一场把词当牌打的战斗；
- 词与词之间没有组合，也没有“用这张卡改变敌人下一步”的循环。

所以“剧情记住用法，战斗反复取用”目前只完成了一半。

## 2. 目标循环

```text
故事单元（事件）
  → 引入 4 个词（契约/认义）
  → 这 4 个词变成手牌（词卡）
  → 3 回合战斗：每回合打 1 张卡
      ├─ 打出 = 一次鉴定（认出或拼出）
      ├─ 成功 = 卡牌效果生效（伤害/护盾/揭示/治疗）
      └─ 失败 = 剧情代价（HP/线索/分支），牌回到弃牌堆
  → 战斗结束（不卡关）
  → 结算：哪些词在战斗中用过、答对/答错
  → SRS：按认义/拼写双轨排下一次
  → 这些词进入下一场战斗的牌库（可组合）
```

关键词：**短单元、可组合、同一个词反复出现**。
不是写一段长剧情，而是写“一个事件 + 一场短战斗 + 4 个词的组合”。

## 3. 一个故事单元的数据草图

```js
storyUnit = {
  id: 'u_lighthouse',
  act: 1,
  conditions: { flagsAll: ['saw_notice'], flagsNone: ['guard_hostile'] },
  introduces: ['guide', 'signal', 'warn', 'reflect'],
  encounter: {
    id: 'e_fog_keeper',
    enemy: '雾中守塔人',
    rounds: 3,
    intents: [
      { round: 1, type: 'attack', damage: 15 },
      { round: 2, type: 'fog', effect: 'hide' },
      { round: 3, type: 'attack', damage: 20 }
    ],
    deckPolicy: 'current + weak'
  },
  rewards: { clues: 1, flags: ['keeper_listened'] },
  branches: [{ ifFlag: 'keeper_listened', next: 'u_lighthouse_after' }]
};
```

每张词卡：

```js
card = {
  wordId: 'guide',
  type: 'spell',           // spell / item / check
  effect: 'reveal',        // shield / damage / heal / reveal / ...
  checkMode: 'recognize',  // 认出：低风险；拼写：高风险
  cost: { hp: 10 },        // 失败时
  upgrade: { spellingConfirmed: 'effect +1 / cost -5' }
};
```

- 牌库不是全词表：默认是**当前故事单元引入的词 + 最近答错的词**；条件/flag 可以改变抽牌。
- 同一个词可以出现在多个故事单元；每次出现都用同一张卡，熟练后升级（认出 → 拼出 → 强化效果）。
- 战斗 3 回合，15 分钟循环里只占 2–3 分钟；失败不卡关，只改结果和线索。

## 4. 示例：旧灯塔 vs 雾中守塔人

**事件**：旧灯塔的灯灭了，守塔人不肯开门；你要在雾里找回三块透镜。

**引入词**：guide / signal / warn / reflect（正好是第 4 幕的 4 个词）。

**战斗**：

| 回合 | 敌人意图 | 玩家手牌 | 打出方式 | 成功 | 失败 |
| --- | --- | --- | --- | --- | --- |
| 1 | 雾墙逼近（攻击 15） | guide / signal / warn / reflect | 选一张，读出/拼出 | guide：揭示透镜位置；warn：让守塔人停手 | 雾墙命中，HP -15 |
| 2 | 守塔人藏进光里（隐身） | 同上 + 弃牌堆 | 认出（低风险）或拼出（高风险） | reflect：照出他的影子；signal：让他回应 | 目标丢失，线索 -1 |
| 3 | 最后一击（攻击 20） | 同上 | 拼出才能强化效果 | 任意拼出成功：护盾/反击；失败：硬吃伤害 | HP -20，但剧情继续 |

战斗结束后：

- 用过的词进入“这场战斗的词”列表；答错的词在 SRS 里拼写回 1 天。
- 答对的词在词书里显示“战斗中使用过”；同一词再用一次，卡牌效果强化。
- 守塔人是否听见（flag `keeper_listened`）决定下一段对话，而不是决定是否通关。

这样剧情、卡牌、SRS 是同一个词的三次出现，而不是三套独立内容。

## 5. 和英语讲义的关系

你上传的英语讲义里最有用的不是“词表”，而是：

- 一词多义/词性变化；
- 固定搭配与例句；
- 近义词辨析（decline/refuse、deny/object）；
- 词根/联想记忆；
- 常见错误。

这些可以变成词卡的**用法注释**和**卡牌选项**，而不是旁白里的装饰。例如：

- `decline` 卡：婉拒（保留关系） vs `refuse` 卡：直拒（触发敌意）；
- `deny` 卡：否认事实；`object` 卡：对决定提出异议；
- 词根提示只在首次契约出现，不在战斗中直接给答案。

原始讲义不提交到仓库；只保留原创的派生例句/搭配和来源说明（设计文档 5.2 的素材规则）。

## 6. 最小可做版本（MVP，已接入）

**第 4 幕已经接入一场 3 回合战斗，用现有的 4 个词**：

1. 进入第 4 幕，契约 4 个词（已有）。
2. 旁白后进入 `e_fog_keeper`：3 回合，每回合 1 张牌。
3. 每张牌显示中文语义 + 效果；玩家选择“认出”（4 选 1 英文）或“拼出”（输入）。
4. 成功结算卡牌效果；失败扣 HP/线索；3 回合后 fail-forward。
5. 结算写入 `battleWords`、`correct/incorrect`；SRS 仍按现有双轨。
6. E2E：一条正确路线、一条失败路线、一次“认出”与“拼出”混用。

不需要新写 48 个词，也不需要新美术；复用现有 `worldSVG`、行动卡样式和 SRS。先证明“同一个词从剧情进入战斗再回到复习”是成立的，再扩故事单元。

## 7. 不抄 BG3 的部分

- 200 万词剧本、17000 种结局、400 人团队、全语音：不现实。
- 要抄的是**组合**：短故事单元、条件、flag、态度、词卡复用。
- 内容量可以靠“短单元 × 可组合词卡 × AI 草稿 + 人审”慢慢积累；不是一次写完。

## 8. 待定问题

1. 战斗默认用“认出”还是“拼出”？建议默认认出（低风险），拼出作为高风险高回报选项。
2. 一场战斗 3 回合是否够？建议先 3 回合，超过 5 回合会挤压 15 分钟循环。
3. 战斗失败是否扣线索？建议扣 HP 或线索二选一，由卡牌内容声明。
4. 牌库默认只带本单元 4 词，还是带“最近错词”？建议 MVP 只带本单元，避免新玩家被旧词压垮。
5. 是否把 BOSS 改成一场 5 回合卡牌战？建议下一版再做，先保住现有五问的确定性。
