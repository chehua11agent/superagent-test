# docs 要点解读

范围：main 分支 `docs/` 下的 design 4 篇、research 3 篇、content 3 篇，共 10 篇（`docs/README.md` 是索引，不单列）。每篇按“结论 / 用途 / 落地”给要点，正文控制在 200 字内。

建议顺序：先读总体设计与三篇设计提案，再读规则、画面两篇调研，最后看内容与数据三篇；动手前先照《闭馆通知》的结构写一个可校验的小样本。

## 1. design/cet4-vocab-rpg.md — 总体设计

**结论**：6 章 288 个四级高频词的文字跑团，标准档每天 15 分钟，先复习后剧情；词即法术/道具/检定，答错扣 HP/线索或走分支但不卡关。
**用途**：这是唯一实现依据，SRS、数值、数据表、API 和验收标准可直接落库落码。
**落地**：先做 1/3/7/16 调度与“复习清空前锁新词”，再按第 8 章搭 API、第 5 章做词表管线；MVP 只做 288 词。

## 2. design/dual-check-design.md — 认义 / 拼写双鉴定

**结论**：“认得出”和“写得出”是两种能力，应拆成认义、拼写两条独立轨道，分别排期、失败和奖励；当前仅 A 拼写加试、E 双徽章、C BOSS 混检已接入。
**用途**：堵住“只做 4 选 1 也能到 mastered”和“拼写失败把认义打回 1 天”的漏洞。
**落地**：先做复习后的拼写加试、词书“会认不会写”筛选和 BOSS 混检；两轨互不重置，双证才算掌握；剧情双路径与契约拼写放后面。

## 3. design/story-card-combat-design.md — 可组合故事单元

**结论**：故事拆成“4 个新词 → 3 回合词卡战斗 → SRS 复习”的可组合单元，同一个词在剧情、战斗、复习各出现一次。
**用途**：让剧情、卡牌、SRS 共用一批词，解决词行动一次性、BOSS 只是五道题的问题。
**落地**：第 4 幕已接入 3 回合 4 张牌、认出/拼出双检定；下一版按 storyUnit 扩单元，牌库只带本单元 4 词，战斗 2–3 分钟，失败仍 fail-forward。

## 4. design/sample-closing-notice.md — 《闭馆通知》样本

**结论**：10 个“拒绝/反对”词、3 幕 5 节点的样本，证明每个词都能落在选项、判定或物品上：5 选项 + 3 判定 + 2 物品，2 个物品各接一次判定。
**用途**：给出可复制的写作流程和可校验 JSON（validate:sample），避免剧情好看但词只当台词装饰。
**落地**：新章节先给每个词指定“位置 + 动作 + 后果”再写旁白；照搬结构扩章，别先写五千字剧情；校验必须过。

## 5. research/trpg-rules-survey.md — 跑团规则与开源基建

**结论**：没有跑团书能兼顾 15 分钟、SRS 与词即行动；用 Ironsworn 做骨架，借 Fate、PbtA、Blades、24XX 各一层，SRS 和词表自研。
**用途**：给出规则层与技术选型；GitHub 无成品，但有可拼基建。
**落地**：别搬 d20/AC/先攻；用 strong/weak/miss 判词并 fail-forward；剧情用 Ink+inkjs，SRS 保持 1/3/7/16。

## 6. research/phb-story-dm-review.md — 5e《玩家手册》盘点

**结论**：PHB 回答“怎么玩”，不回答“玩什么故事”和“怎么当 DM”；只有零散设定种子、裁定提示和人物/饰品表，没有战役/模组/DM 章。
**用途**：别指望 PHB 给现成剧情或 DM 指南；可借探索/社交/战斗、三步循环、NPC 三态度、激励、背景四表、d100 饰品和四阶段格局。
**落地**：把这些当写作模板和随机钩子，不抄译文/表格；遭遇、NPC、战役管理自写或参考 DMG；用 SRD 划版权边界。

## 7. research/game-visual-solutions-survey.md — 画面 / UI 方案

**结论**：没有一键换皮方案，也不必换引擎；推荐 A 原地游戏化（1–3 天）→ B PixiJS 渲染层（1–2 周）→ C 视觉小说引擎（暂不做）。
**用途**：给低风险视觉升级路线与许可边界，保住现有测试和离线能力。
**落地**：用 game-icons、立绘、卡框、动效音效做 A，拍 Before/After；长线做数据化、Vite/TS、资源管线与编辑器；暂不换 Phaser/WebGAL/Godot。

## 8. content/cet4-dnd-mechanics-vocab.md — DnD 机制词汇表

**结论**：5 类 × 10 机制 × 3 词 = 150 个四级词映射到 5e 机制，全部在大纲内、无重复；这是可玩切片，不是按真题词频排序的最终 288 词。
**用途**：提供“词 → 机制 → 卡牌/事件/解密”的选词与玩法模板。
**落地**：把 JSON 导入词卡，按分类映射 card_type/effect_tag；先补足 138 词，再按词频排序；这些词只当玩法样本，别当最终词表。

## 9. content/cet4-syllabus-kb.md — 四级大纲知识库

**结论**：四级大纲知识库已有 4530 个唯一词头及中文释义；OCR 在《你还在背单词吗》中高置信定位 3629 词（80.1%），769 词未定位但保留。
**用途**：词义可全量查询、词条页可回溯，适合扩表、补词和核对 288 词是否超纲。
**落地**：用 JSON 做词义/页码查询，用 book_pages 回查例句；未定位词不要丢；先接真题词频排序和玩法分层再批量出内容；OCR 定位数不能当精确词数。

## 10. content/cet4-materials-ingest.md — 两本素材录入核对

**结论**：两本素材 OCR 完整（363/363、471/471，无缺页）：前者可做词卡、填空、辨析；后者可做语法、写作、翻译、听读题，但未拆题目/答案。
**用途**：确认素材够用；manifest 记录页数、字符数和 SHA-256，可复现可追溯。
**落地**：按页从 JSONL 回查原文出题，规则/人工校对 OCR 噪声；全文因版权不入公开仓库，只交 manifest；book2 先做题目/答案结构化。

## 建议动手顺序

1. 先按总体设计实现 1/3/7/16 调度与复习闸门。
2. 用双鉴定补拼写轨，再按《闭馆通知》的结构做一章可校验内容。
3. 内容稳定后再做画面 A 路线，最后扩词表与素材管线。
