# 拾词者 · 雾港

一个用英语玩的文字跑团原型。第一章《雾港》可以完整游玩：12 幕、48 个 CET-4 词、4 天一轮、章节终局 BOSS。

> 判断标准只有一条：去掉英语部分，它还值得玩吗？
> 这个原型先回答下一问：至少，雾港值得走一遍。

## 运行

不需要安装任何依赖：

```bash
npm run serve
# 打开 http://127.0.0.1:4173/
```

不要直接用 `file://` 打开 `game/index.html`，浏览器的模块与 JSON 加载会被拦截。

## 操作

- **开始新的航程**：从第 1 天、第 1 幕开始，12 个新词分 3 幕契约。
- **体验演示存档**：载入“昨天已学过 3 幕”的存档，今天有 12 张到期卡，可直接体验复习优先的完整循环。
- 结算页的 **快进一天（原型演示）** 会把本地时钟推进一天，用来查看第二天的复习队列；它不是正式玩法。
- 词书里可以把“已认识”的词撤销回复习队列。

## 已实现

| 模块 | 内容 |
| --- | --- |
| 每日循环 | 复习 → 剧情 → 结算；到期未清空时锁定新词与剧情 |
| SRS | 认义 1/3/7/16 天 + 拼写 1/3/7 天双轨；认义错只回认义，拼写错只回拼写；双证才算 mastered |
| 词行动 | 每幕 1–2 张词卡；卡面只给中文语义与效果，英文由玩家输入（拼写检定）；失败结算 HP / 线索 / 分支；没有“卡关” |
| 契约 | 先展示英文、音标、释义、例句，再立即做认义小测；答错仍进入 1 天复习 |
| 已认识 | 中文 → 英文拼写验证；通过后移入词书，不进入 SRS；可撤销 |
| 章节 | 第一章 12 幕 × 4 词；每天 3 幕；第 12 幕后进入 5 问 BOSS（3 认出 + 2 拼出，答对 3 问净化） |
| 词卡战斗 | 第 4 幕「旧灯塔」的 4 个词变成手牌，3 回合、敌人意图、认出/拼出双检定、失败扣 HP/线索；可跳过，不卡关 |
| 可视化 | 程序化 SVG 雾港全景：12 个镜头、昼夜/风暴/黎明、雾、雨、灯塔光束、灯笼、海面；章节地图与节点 |
| 存档 | localStorage；跨天以本地 04:00 为学习日边界 |
| 可访问性 | 键盘焦点样式、跳过链接、减少动效（手动开关 + `prefers-reduced-motion`）、移动端布局 |

## 内容小样本：《闭馆通知》

按“先做 10 个词，再扩章节”的方式，在 `content/samples/closing-notice.json` 做了一个拒绝/反对类词的小样本：

- 10 个词：decline / refuse / ignore / resist / deny / object / reject / forbid / prohibit / oppose
- 3 幕、5 个节点、4 个结局
- 5 个词落在**选项**，3 个落在**判定**，2 个落在**物品**；两个物品还各自接到一次判定
- `npm run validate:sample` 会拒绝“只写进句子、没有功能位置”的词

设计说明见 [`docs/sample-closing-notice.md`](../docs/sample-closing-notice.md)。它目前是内容设计样本，没有接进第一章的 UI。

## 端到端测试

`e2e/game.spec.mjs` 用真实浏览器跑完整路径：

1. 新游戏：封面 → 3 幕（12 契约 + 3 词行动）→ 结算 → 快进 → 12 张到期复习。
2. 演示存档：复习优先，12 张清空后才进入契约。
3. 已认识：验证跳过 → 词书筛选 → 撤销。
4. 失败前进：答错扣 HP、SRS 回 1 天，剧情仍到第 5 幕。
5. 硬闯：不测试单词，固定 HP -15，仍然推进。
6. 拼写加试：认义答对后可加试拼写，词书出现双轨徽章。
7. 词卡战斗：第 4 幕的词变成手牌，3 回合内推进剧情。
8. BOSS：3 认出 + 2 拼出，五问答对三问净化 → 章节结算。
9. 设置与重置：减少动效、锚点时间、清档回封面。
10. 移动端：首页 CTA、复习选项、剧情契约按钮均在首屏，无横向溢出。

测试会收集 `pageerror` 与 console error；任何浏览器错误都会让对应用例失败。

## 双鉴定：认识 vs 会拼（A/E/C 已接入）

现在复习/契约考“认义”，词行动/BOSS/已认识考“拼写”，两条能力分成独立的 `stage` 与到期日：

- 认义：1/3/7/16 天，4 选 1，失败只回认义队列；
- 拼写：1/3/7 天，独立到期；剧情里拼写失败才扣 HP/线索，不重置认义；
- `mastered` 必须“认义 3 + 拼写 ≥2”；“已认识”必须通过拼写；
- 已接入：复习后的拼写加试、词书双徽章/“会认不会写”筛选、BOSS 3 认出 + 2 拼出；
- 未接入：剧情“认出/拼出”双路径、听写/语境/近义辨析/词形变化。

实现范围：A（复习拼写加试）+ E（词书双徽章）+ C（BOSS 混检）。完整提案、状态草图、B/D 等后续项见 [`docs/dual-check-design.md`](../docs/dual-check-design.md)。

## 剧情 → 词卡战斗 → 复习

第 4 幕「旧灯塔」已接入一场 3 回合词卡战斗：剧情里契约过的 guide / signal / warn / reflect 变成手牌；每回合选一张卡，用认出（4 选 1）或拼出（输入）打出；成功结算卡牌效果，失败扣 HP/线索；战斗结果回到剧情，词进入 SRS。设计笔记见 [`docs/story-card-combat-design.md`](../docs/story-card-combat-design.md)。

## 原型边界（诚实说明）

- **单机、客户端权威**：SRS / HP / 线索都在浏览器里计算；正式版应按设计文档由服务端权威结算。
- **词频是占位排序**：`freq_rank` 是本章叙事顺序，不是 15 份真题语料跑出的词频。正式版需要按设计文档 5.2 的抽取/清洗/加权管线生成 288 词。
- **只做了第一章**：第二章到第六章在界面上锁定；章节切换、词包扩展未实现。
- **每日档位固定 12 词**：10 / 12 / 15 / 20 的档位切换需要“半幕暂停”等额外逻辑，未在原型里做。
- **社交与服务端能力未做**：异步挑战码、小队周目标、服务端账号、推送通知、休整券/回归任务都不在原型里。
- **没有音频**：音标与例句可读，但 TTS、发音评分、环境音未接入。
- **内容仍是一稿**：48 个词、23 个行动、12 段旁白均为原型原创，需要内容审校与试玩平衡。
- **双鉴定只接了 A/E/C**：剧情里的“认出/拼出”双路径、听写、语境、近义辨析、词形变化还没接。
