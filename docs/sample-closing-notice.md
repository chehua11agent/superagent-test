# 小样本：《闭馆通知》

> 10 个“拒绝 / 反对”类 CET-4 词 · 3 幕 · 5 个节点。
> 目的只有一个：看每个词能不能被放进**选项、判定或物品**，而不是只写进一句旁白。

## 0. 为什么先做这个

如果直接写完整剧本，很容易出现“剧情很好看，但单词只是台词里的装饰”。
这个样本把范围压到 10 个词，强迫每个词回答一个问题：

**玩家在什么时候、用什么动作、承担什么后果地用到这个词？**

样本的机器可读版本在 [`game/content/samples/closing-notice.json`](../game/content/samples/closing-notice.json)，
结构校验在 `npm run validate:sample`。

## 1. 10 个词与它们的位置

| 词 | 中文 | 位置 | 节点 | 玩家做什么 | 为什么不是“只写进句子” |
| --- | --- | --- | --- | --- | --- |
| decline | 婉拒；谢绝 | **选项** | n2 值班台 | 婉拒馆员“明天再来”的建议 | 选它，馆员会偷偷递出读者卡；选 refuse 会触发呼叫铃 |
| refuse | 拒绝 | **选项** | n2 值班台 | 直接拒绝馆员的解释，要求立刻开门 | 和 decline 并排成两个真实选项，门会开但玩家被记名 |
| ignore | 忽视；不理会 | **选项** | n3 闭馆之后 | 无视警报，沿书架摸黑走 | 选它可绕过守卫，但失去墙上的湿脚印线索 |
| resist | 抵抗；抵制 | **判定** | n3 闭馆之后 | 说出 resist，推开被旧报纸顶住的消防门 | 失败会引来守卫；成功才拿到“注销章”物品 |
| deny | 否认 | **判定** | n4 馆长办公室 | 说出 deny，逼馆长把“这本书不存在”再说一遍 | 成功时她漏掉一个日期，失败时她合上登记册 |
| object | 反对 | **选项** | n4 馆长办公室 | 对注销单正式提出异议 | 和 deny（质疑事实）是两条不同的路：object 让程序暂停 |
| reject | 拒绝；驳回 | **物品** | n3 / n4 | 获得“馆长的注销章”，用它驳回伪造注销单 | 物品不是自动通关：使用时仍要说出 reject；没走 resist 线就拿不到 |
| forbid | 禁止 | **物品** | n1 → n5 | 拿走“湿掉的闭馆通知”，第 5 节点出示它 | 不拿就解锁不了最终条例判定；它是物品，不是旁白 |
| prohibit | （法规、条例）禁止 | **判定** | n5 闭馆之后的第一句话 | 引用条例，说出 prohibit，阻止馆长把书带走 | 和 forbid 分工：告示/个人说 forbid，制度说 prohibit |
| oppose | 反对；对抗 | **选项** | n5 闭馆之后的第一句话 | 直接反对馆长最后那句话 | 不引用条例的另一条结局路径，通向“对峙” |

覆盖：**5 个选项 + 3 个判定 + 2 个物品 = 10 个词**。
另有 2 个物品 → 判定联动：`forbid` 物品触发 `prohibit` 判定，`reject` 物品触发 `reject` 判定。

## 2. 三幕 · 五节点

### 第一幕 · 通知

**n1 玻璃门上的通知**

> 雨把闭馆通知贴湿了一角。门内只剩值班台的灯，馆员正把最后一摞书推进还书箱。你要找的那本书还在馆里。

- **物品**：把通知揭下来 → 获得「湿掉的闭馆通知」（`forbid`）。这是可选的；不拿，第 5 节点的条例路就关闭。
- **选项**：敲门问通融；或绕到侧门看窗。都进入 n2。

**n2 值班台**

> 馆员隔着玻璃说：系统已经结了今天的账。她可以明天帮你留书，但不能现在开门。她的手指停在「闭馆」键上。

- **选项 A（decline）**：婉拒她的建议，请她通融一次 → 她递出读者卡，进入 n3。
- **选项 B（refuse）**：直接拒绝她的解释，要求开门 → 门开了，但被记名，进入 n3。
- **选项 C（无词）**：接受“明天再来” → 提前结局 `end_leave`。

这一幕是核心对照：**两个“拒绝”不是同义词替换，而是两种社交力度、两种后果。**

### 第二幕 · 例外

**n3 闭馆之后**

> 门在背后合上。值班台的灯灭了，走廊尽头的消防门却一下一下地响，像有人从另一边推。

- **选项（ignore）**：无视警报，沿书架摸黑走 → 进入 n4，但失去湿脚印线索。
- **选项 → 判定（resist）**：去推被顶住的消防门 → 成功获得「馆长的注销章」（`reject` 物品）和脚印线索；失败引发守卫警觉。
- **物品获取是路径相关的**：走潜行线就拿不到注销章，第 4 节点的 `reject` 路会关闭。

### 第三幕 · 留灯的人

**n4 馆长的办公室**

> 馆长还在。她把一张注销单推到你面前，说这本书从未入藏。你看见她手边的钥匙，也看见她压住的那页登记。

- **选项（object）**：对注销单提出正式异议 → 她必须停下来回应，进入 n5。
- **选项 → 判定（deny）**：逼她把“这本书不存在”再说一遍 → 成功得到日期缺口，失败她把钥匙收进抽屉。
- **选项 → 物品判定（reject）**：用注销章驳回伪造注销单（需要 `item_stamp`）→ 成功作废注销单，失败表单被收走。

**n5 闭馆之后的第一句话**

> 馆长把书放回桌上：闭馆之后，图书馆不属于任何人。你手里还握着那张湿掉的闭馆通知。

- **选项 → 物品判定（forbid → prohibit）**：把通知拍在桌上，引用条例（需要 `item_notice`）→ 说出 prohibit 则进入 `end_lamp`，失败进入 `end_close`。
- **选项（oppose）**：反对她最后那句话 → `end_confront`。
- **选项（无词）**：把书放回原处，留下通知 → `end_close`。

## 3. 路径与结局

| 结局 | 怎么到达 | 玩家失去什么 / 得到什么 |
| --- | --- | --- |
| **留灯** `end_lamp` | 拿走通知，在 n5 通过 `c_prohibit` | 得到条例线索，灯亮到天亮 |
| **对峙** `end_confront` | 在 n5 选择 oppose | 没有引用制度，靠自己顶回去 |
| **闭馆** `end_close` | n5 引用失败，或选择安静离开 | 书被带走/放回，闭馆灯灭一盏 |
| **明天再来** `end_leave` | n2 接受馆员的建议 | 提前结束，保留“明天”的入口 |

## 4. 四组语义对照

| 对照 | 区别 | 在本样本里的功能位置 |
| --- | --- | --- |
| decline / refuse | 婉拒保留关系；直拒伤面子 | n2 两个并排选项，后果不同 |
| forbid / prohibit | 人/告示的禁止；法规/条例的禁止 | forbid 是物品（通知），prohibit 是它触发的条例判定 |
| deny / object | 否认事实；对决定提出正式异议 | n4 两条不同的判定/选项 |
| reject / refuse | 驳回文件/申请；拒绝人的请求 | reject 是注销章物品，refuse 是 n2 的人际选项 |

这四组如果只写成句子，玩家不会感到区别；放进选项和判定后，选错会真的改变下一步。

## 5. 验证

```bash
npm run validate:sample
```

输出会把每个词的主位置列成表，并检查：

- 10 词 / 3 幕 / 5 节点；
- 每个词都有一个 `primary_placement`，且指向真实存在的选项/判定/物品槽；
- 槽里的 `word_id` 与词一致；
- 所有 `next` / `end` 指向存在的节点或结局；
- 每个节点至少有一个可操作槽和出口；
- decline 与 refuse 同节点；forbid 是物品、prohibit 是判定；
- 物品词都有 `use_check`，不是只能看不能用的摆设。

## 6. 这个样本不是什么

- **不是完整剧本**：只有 5 个节点，没有 6 章、没有 SRS 排期、没有战斗数值。
- **不是已接入当前原型的章节**：JSON 是内容设计的可校验样本；当前 `第一章 · 雾港` 的 UI/引擎还没有加载它。
- **没有做完美术**：它验证的是词在玩法结构中的位置，不是画面表现。
- **不是最终词表**：这 10 个词是按“拒绝/反对”主题挑的样本，不代表真题词频顺序。

## 7. 结论

这个样本能回答的问题：

> 10 个词里，有没有一个只是“写进句子”？

答案：**没有**。10 个词全部落在选项、判定或物品上；其中 2 个物品还各自接到一次判定。
下一步如果是扩成完整章节，应该先复制这个结构，而不是先写 5000 字剧情。
