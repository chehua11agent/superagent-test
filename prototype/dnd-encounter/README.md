# 苔灯旅店 · D&D 式一夜

一个单页、可试玩的垂直切片：**3 段剧情 + d20 检定 + 1 场回合制战斗 + 复习结算**，4 个 CET-4 单词贯穿全程。

> 试玩：<https://chehua11agent.github.io/superagent-test/prototype/dnd-encounter/>
>
> 目的不是做一个成品，而是回答一句判断：**D&D 这套「检定 + 分支 + 回合制战斗」值不值得为《拾词者》继续写下去。**

## 一分钟了解

- 你是拾词者。雾夜，桥头的苔灯旅店；一个没有脸的抄写员，每夜从账本上抄走一个词。
- 剧情里做 3 次选择：亮徽章、说服守桥人、绕后门；看苔灯、翻账本、在炉边暖手。每幕各有 2 个可选的 d20 检定（说服 / 隐匿、洞悉 / 奥秘），结果会改变战斗条件，失败也继续。
- 战斗是标准的 D&D 回合制骨架：先攻、AC、d20 + 命中、伤害骰、暴击 / 大失败、优势 / 劣势、法术位、敌人意图、失败推进。
- 4 个词先在剧情里出现，再变成 4 张词术卡：`ward` 守护、`scorch` 灼烧、`mend` 修补、`daze` 恍惚。施放前要选对词义；选错，法术散掉，回合结束。
- 战斗结束回到剧情尾声，再进入「四个词，明天再见」的复习结算（认义 1 题 + 拼写 1 题）。

约 3–5 分钟。手机与桌面均可玩。

## 运行

不需要安装依赖，也不需要构建：

```bash
python3 -m http.server 8000
# 打开 http://127.0.0.1:8000/prototype/dnd-encounter/
```

也可以直接双击 `index.html`（页面不发起任何 fetch，`file://` 可用）。

键盘：`1` 长剑、`2` 闪避、`3` 药水、`4` 苔铃；`Q/W/E/R` 对应四张词术；`Enter` 继续。

## 这张演示想验证什么

1. **检定能不能让选择有重量。** 不是「选 A 或 B」，而是「你敢不敢把结果交给 d20」；失败不是读档，而是换一种代价继续。
2. **回合制会不会打断阅读。** 一场 3–5 回合的战斗，能不能比五道问答题更像「打了一场」。
3. **词能不能同时是剧情道具和战斗动作。** `ward` 先在灯罩上出现，再变成 +3 AC；`scorch` 先在烧焦的斗篷上出现，再变成 2d6 火焰。同一个词出现三次：剧情、战斗、复习。
4. **内容成本。** 这一夜大约是一幕的量；乘以 12 幕，就是一章。值不值得写，看试玩后的判断。

## 已知边界（诚实说明）

- **只有一夜。** 1 场遭遇、2 个检定、4 个词；没有多场战斗、条件分支树、存档、商店、词库成长。
- **数值只调了一轮。** 命中率、HP、伤害是让演示能打完的量级，不是平衡性结论；两三个随机结果就能改写战斗走向（这正是 d20 的特点，但正式版需要更多样本）。
- **不是完整 SRS。** 结算页只展示「会怎么进复习」，没有实现 1/3/7/16 天调度、跨天存档、拼写 / 认义双轨。
- **复习只有 2 题。** 认义 1 题 + 拼写 1 题，用来展示结算接口，不是评估。
- **没有 TTS / 语音、没有角色立绘、没有 3D。** 场景是程序化 SVG，和《雾港》同一路线；3D 方案的调研见 [`docs/research/3d-scene-assets-github.md`](../../docs/research/3d-scene-assets-github.md)。
- **品牌与版权。** 只借用 SRD 级别的通用机制（d20、AC、HP、优势 / 劣势），没有使用《龙与地下城》的文本、美术、标志或官方角色；故事、名词与文本均为原创。
- **失败结局也是设计的一部分。** 倒下不会卡关，会进入「词被抄走了」的尾声并照常结算——这是 D&D「fail forward」在这类学习产品里的用法。

## 验证记录（2026-11-14）

用 Playwright（Chromium）在本地静态服务器上跑过：

- 主线：封面 → 3 幕 → 苔灯检定成功 → 战斗 → 施放 `ward`（词义检定）→ 击杀 → 尾声 → 结算 → 两题 → 结束页；无 console error、无 page error、无外部请求。
- 失败线：说服检定失败扣 3 HP → 暖手回满 → 战斗 → 一直闪避直到倒下 → 失败尾声 → 仍可结算。
- 移动端 390×844：标题、剧情、战斗三屏无横向溢出；战斗底栏完整在视口内（含状态条、4 张词术、4 个动作）。
- `file://` 直接打开可玩。
- 桌面 1440×1000：无横向溢出。
